ユーザーが学習中に「気になったこと」「気づいたこと」を書き留めたいので、`points/` ディレクトリに記録してください。

## ユーザーのメモ

$ARGUMENTS

## 手順

1. `points/README.md` を読み、ルールとフォーマットを確認する。
2. メモをトピックごとに分ける(1つのメモに複数の話題が含まれていれば分割する)。
3. 各トピックについて、`points/` 内に同じトピックのファイルがあるか探す。
   - ある → そのファイルに今日の日付の `## YYYY-MM-DD` 見出しで追記する(既にその日付の見出しがあればその下に追記)。
   - ない → `points/YYYY-MM-DD_トピック名.md` を新規作成する。トピック名は英小文字のケバブケース(例: `server-components`)。
4. 「気になったこと / 気づいたこと」にはユーザーのメモを**意味を変えずに**書く。言い回しの整理は最小限にとどめる。
5. 「補足・解説」には、このプロジェクト(Next.js App Router の dashboard)のコードや公式ドキュメントの知識をもとに、短く要点だけ書く。関連するコードがあれば `path:line` で場所を示す。確信がないことは書かない。
6. ユーザーのメモが疑問形なら、分かる範囲で答えを補足に書き、分からない部分は「未解決・あとで調べる」に残す。該当がなければその見出しは省略してよい。
7. 「参考リンク」に、補足・解説の根拠を確認できるリンクを書く。
   - 公式ドキュメント(Next.js / React / Vercel など)を優先する。
   - 補足の中で「公式では〜とされている」のように出典に触れた箇所は、必ず対応するリンクを付ける。可能ならページ内の該当セクション(`#anchor`)まで指定する。
   - 各リンクには「何が確認できるか」を一言添える(例: `- [Project structure and organization](URL) — 代表的な3つの構成方針`)。
   - リンクは WebFetch などで**実際に開いて内容を確認したものだけ**を書く。記憶だけで URL を書かない。確認できなかった場合はその旨を書く。
8. 最後に、作成・追記したファイルのパスと、各トピックを1行ずつ報告する。

## 注意

- 日本語で書く。技術用語・コード識別子は原文のまま。
- `points/` 以外のファイル(アプリのコード)は変更しない。
- メモが空の場合は、何を記録したいか尋ねる。
